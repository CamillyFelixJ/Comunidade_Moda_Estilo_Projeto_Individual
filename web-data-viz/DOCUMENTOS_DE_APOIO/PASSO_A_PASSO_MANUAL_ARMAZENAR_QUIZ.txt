Passo a passo (manual) — o que VOCÊ deve fazer nas pastas/arquivos do projeto

Objetivo
Salvar respostas do quiz no banco MySQL e disponibilizar os dados para a dashboard.

Importante: este arquivo contém apenas instruções. NÃO ALTERE NENHUM ARQUIVO AUTOMATICAMENTE — siga os passos e implemente você mesmo.

Arquivos/pastas do projeto que serão usados (referência):
- API: web-data-viz/app.js
- Config DB: web-data-viz/src/database/config.js
- Script de criação de tabelas: web-data-viz/src/database/script-tabelas.sql
- Models existentes: web-data-viz/src/models/*.js (ex.: usuarioModel.js, medidaModel.js)
- Rotas existentes: web-data-viz/src/routes/*.js
- Controllers existentes: web-data-viz/src/controllers/*.js
- Front-end quiz: web-data-viz/public/quiz.html
- Dashboard front-end: web-data-viz/public/dashboard/*.html

Resumo das ações que você precisa fazer (sequência recomendada)

1) Criar tabela no banco MySQL
--------------------------------------------------
Arquivos afetados: nenhum arquivo do repositório — você deve executar SQL no seu MySQL.

No MySQL (use seu cliente ou Workbench) execute um script para criar a tabela de respostas. Sugestão:

CREATE TABLE quiz_resposta (
    id INT PRIMARY KEY AUTO_INCREMENT,
    fk_usuario INT NULL,
    data_envio DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    principal VARCHAR(50),
    percentuais JSON,
    respostas JSON,
    resultado_json JSON,
    FOREIGN KEY (fk_usuario) REFERENCES usuario(id_usuario)
);

Observações:
- Se sua versão do MySQL não suportar JSON, troque os campos JSON por TEXT.
- Você pode executar este comando junto aos outros do arquivo web-data-viz/src/database/script-tabelas.sql.

2) Criar model que salva/consulta respostas
--------------------------------------------------
Criar: web-data-viz/src/models/quizModel.js

O que implementar (seguindo padrão do projeto):
- require do database: var database = require("../database/config");
- exportar funções como salvarResposta, listarPorUsuario e contarPorPerfil.

Exemplo de assinatura (descrição):
- salvarResposta(fkUsuario, principal, percentuaisJSON, respostasJSON, resultadoJSON)
  -> monta SQL INSERT INTO quiz_resposta ... e usa database.executar(instrucao)
- listarPorUsuario(fkUsuario) -> SELECT * FROM quiz_resposta WHERE fk_usuario = ...
- contarPorPerfil() -> SELECT principal, COUNT(*) AS total FROM quiz_resposta GROUP BY principal

Aviso de segurança: o projeto usa concatenação SQL em outros models. Para aprendizado, mantenha o estilo. Em produção, prefira queries parametrizadas.

3) Criar controller para receber o POST do front-end
--------------------------------------------------
Criar: web-data-viz/src/controllers/quizController.js

Funções a implementar:
- receberResposta(req, res)
  - espera body: { fkUsuario, respostasUsuario, resultado }
  - valida payload
  - extrai principal do resultado (resultado.principal.chave) se existir
  - chama quizModel.salvarResposta(...) com JSON.stringify nos campos complexos
  - retorna 201 com { id: insertId } ou erro 500

- obterContagemPerfis(req, res)
  - chama quizModel.contarPorPerfil() e retorna JSON

4) Criar rota para quiz e registrar em app.js
--------------------------------------------------
Criar: web-data-viz/src/routes/quiz.js

Conteúdo mínimo (descrição):
- express.Router()
- router.post('/responder', quizController.receberResposta)
- router.get('/contagem-perfis', quizController.obterContagemPerfis)

Registrar em: web-data-viz/app.js
- no topo onde há outras rotas require:
    var quizRouter = require("./src/routes/quiz");
- e depois registrar: app.use("/quiz", quizRouter);

5) Alterar o front-end (APENAS se quiser) — enviar resultado ao backend
--------------------------------------------------
Arquivo: web-data-viz/public/quiz.html

O que você deve editar: função finalizarJogo() (no final do arquivo). Substitua por uma versão que, após calcular o resultado e salvar em localStorage, envie um POST para /quiz/responder com o body:

{
  fkUsuario: sessionStorage.ID_USUARIO || null,
  respostasUsuario: respostasUsuario,
  resultado: resultado
}

Use fetch com 'Content-Type': 'application/json'. Trate erros no catch (apenas log ou aviso ao usuário).

Observação: você pediu para NÃO ALTERAR CÓDIGOS — portanto este passo é só um guia. Se não quiser enviar ao backend, mantenha apenas o localStorage.

6) Ajustar a dashboard para consumir os dados do backend
--------------------------------------------------
Arquivos a editar (exemplos): web-data-viz/public/dashboard/dashboard.html ou web-data-viz/public/dashboard/cards.html

Chamadas recomendadas:
- Para KPI de perfil (perfil predominante): fetch('/quiz/contagem-perfis').then(r => r.json())
- Para distribuir estilos (pergunta 1) você pode consultar a tabela quiz_resposta.respostas (JSON) com JSON_CONTAINS ou criar endpoints adicionais no controller que retornem os dados já agregados.

Sugestão prática: comece consumindo /quiz/contagem-perfis e desenhe um gráfico de pizza/bar com os resultados.

7) Testes locais
--------------------------------------------------
1. Verifique web-data-viz/.env.dev ou .env com credenciais do MySQL (DB_HOST, DB_USER, DB_PASSWORD, DB_DATABASE, DB_PORT).
2. Execute o script SQL para criar a tabela quiz_resposta.
3. Start a API: no diretório web-data-viz rode npm install e o comando de start (ver package.json).
4. Abra a UI (acesse http://HOST:PORT) e realize o quiz.
5. Verifique a tabela quiz_resposta no banco para confirmar o registro.
6. Teste os endpoints criados com Postman ou fetch no browser.

8) Considerações e próximos passos (opcionais)
- Normalizar respostas: se quiser relatórios mais fáceis (e melhores performances em agregações), crie tabela quiz_resposta_item com colunas (fk_quiz_resposta, pergunta_id, valor, posicao, nota) e persista os itens individualmente além do JSON bruto.
- Autenticação: hoje o login salva sessionStorage.ID_USUARIO; se você quiser segurança maior, use tokens e autentique as rotas.
- Segurança: sanitize/valide os campos no controller antes de construir SQLs.
